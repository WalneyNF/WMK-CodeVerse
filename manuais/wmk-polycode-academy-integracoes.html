1. Escolher uma arquitetura

São três mecanismos distintos: transpilação (Portugol → GDScript), runtime + binding (Lua/JavaScript controlando objetos Godot) e processo externo (PHP, APIs e bancos via HTTP). Uma GDExtension adiciona código nativo, mas não transforma automaticamente uma linguagem em script de nó.

LINGUAGEM → [transpilador] → GDScript → Godot
LINGUAGEM → [runtime + binding] → Object / Variant / ScriptInstance
PHP / API → [HTTPS / JSON] → cliente HTTP Godot

2. Laboratório Portugol: passo a passo

Pré-requisitos: Python 3.10+ e Godot 4.x. Baixe o WMK CodeVerse.

git clone https://github.com/WalneyNF/WMK-CodeVerse.git
cd WMK-CodeVerse
py wmk-portugol/compilador.py wmk-portugol/exemplos/ola_mundo.por
py -m unittest discover -s wmk-portugol -p "test_*.py" -v

Abra compilador.py: estude tabelas de tipos e palavras reservadas, transformação de expressões, blocos e geração de código. Crie no Godot uma cena com nó Node2D, adicione o arquivo ola_mundo.gd gerado e execute. O resultado deve incluir WMK_PORTUGOL_OK na saída.

O compilador atual é um subconjunto educacional. Não aceita Portugol Studio completo, nem executa arquivos .por diretamente no Godot. Para expandir, implemente lexer → parser → AST → validação semântica → emissor e testes com erro por linha.

3. Exemplo PHP: comunicação externa

Crie php-api/estado.php:

<?php
header('Content-Type: application/json');
echo json_encode(['jogador'=>'WMK', 'vida'=>100]);

Inicie somente localmente:

php -S 127.0.0.1:8787 -t php-api

No Godot, crie Node + HTTPRequest filho e anexe este GDScript ao Node:

extends Node
@onready var http: HTTPRequest = $HTTPRequest

func _ready() -> void:
    http.request_completed.connect(_resposta)
    var erro := http.request("http://127.0.0.1:8787/estado.php")
    if erro != OK:
        push_error("Falha ao iniciar HTTP: %s" % erro)

func _resposta(resultado: int, status: int,
        _cabecalhos: PackedStringArray, corpo: PackedByteArray) -> void:
    if resultado != HTTPRequest.RESULT_SUCCESS or status != 200:
        push_error("HTTP falhou")
        return
    var dados = JSON.parse_string(corpo.get_string_from_utf8())
    if typeof(dados) != TYPE_DICTIONARY:
        push_error("JSON invalido")
        return
    print("WMK_PHP_OK ", dados.get("jogador"))

Isso comprova Godot ↔ PHP via HTTP, não PHP nativo na cena. O servidor embutido é para desenvolvimento, não produção. Se desejar script PHP anexável ao nó, será preciso estudar embedding do runtime PHP, bindings Godot, ciclo de vida, memória, threads, distribuição e exportação.

4. Como integrar uma linguagem nativa

Estude ScriptLanguage, ScriptInstance e registro de GDScript. Implemente carregamento de script, instâncias por nó, mapeamento Variant, métodos, propriedades, sinais, erros, depuração e exportação. O guia arquitetural detalhado acompanha esse trabalho.

5. Provedores, agentes e MCP

Provedor de modelo (Ollama, Groq, OpenAI, Gemini, Anthropic) não é a mesma coisa que agente (OpenCode, Codex, Claude Code). Eles precisam de adaptadores diferentes. Interfaces candidatas incluem ACP/servidor do OpenCode, app server do Codex e SDK/CLI documentados do Claude Code. Não estão integrados no editor ainda.

O wmk-ai/ possui clientes CLI iniciais e servidor MCP de leitura. Um painel futuro precisa de cadastro, seleção de modelo, armazenamento seguro de credenciais, aprovação antes de escrever arquivos, limites de uso e logs de auditoria.

6. Jogos com bancos de dados

Jogo Godot → HTTPS → API autenticada (PHP/Python/Node)
                                     ↓
                     MySQL / MariaDB / PostgreSQL
                     ou Supabase com regras RLS

Use SQLite para armazenamento local/offline. Nunca distribua senha root de MySQL, credenciais de serviço ou chaves secretas no jogo. Para Supabase no cliente, configure autenticação e Row-Level Security; chaves secretas pertencem ao backend. Valide toda pontuação, economia e inventário no servidor.

7. Compilar, verificar e contribuir

O projeto usa uma branch de integração separada da base histórica do Godot. O manual Compilação reproduzível no Windows contém versões fixadas, comandos, etapas do Actions, erros conhecidos e critérios de conclusão.

Uma integração só deve ser anunciada como pronta após build aprovado, execução de cena real, testes de erro, exportação, documentação e licenças verificadas. Traga um projeto mínimo, script de teste, versões e logs completos para cada contribuição.
