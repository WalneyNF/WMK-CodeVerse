WMK CodeVerse — Manual de Testes

Instalação no Windows, download, cenas JavaScript e Lua, resultados esperados e solução de problemas.

1. O que já foi confirmado?

Execução 43905108907: workflow concluído com sucesso.

Passaram as etapas de compilação Windows, JavaScript com cena real, instalação da extensão Lua e execução de cena Lua. A versão contém exemplos WMK-JS-Demo e WMK-Lua-Demo.

Atenção: GDScript e C# possuem suporte no motor Godot, mas não são equivalentes a testes automatizados de jogos completos. A interface gráfica no PC e a movimentação de personagens precisam de testes manuais. A edição aqui compilada tem base Godot 4.6.1, não 4.7.

2. Como baixar

  1. Abra Releases do WMK-CodeVerse.
  2. Selecione a versão marcada Pre-release e baixe WMK-CodeVerse-Windows-Preview.zip em Assets, caso esteja publicada.
  3. Se a Release ainda não aparecer, abra a compilação aprovada e baixe WMK-Godot-Five-Languages-Windows em Artifacts. Esse download pode exigir login e expira em 30/11/2026.
  4. Extraia o ZIP completamente em D:\Ferramentas\WMK-CodeVerse\. Não execute o programa diretamente de dentro do ZIP.
  5. Mantenha o diretório GodotSharp ao lado do EXE, sem mover somente o programa.

3. Abrir pela primeira vez

  1. Localize o arquivo que contém editor e termina em .exe (não o .console.exe).
  2. Dê dois cliques e confirme que a janela do editor abre.
  3. Na opção Editor Settings, selecione idioma português, quando disponível.
  4. Crie um projeto vazio, adicione um nó e salve uma cena. Esse é o teste básico de edição.

Se a janela não abrir, execute o arquivo com sufixo .console.exe pelo PowerShell para observar eventuais mensagens, sem apagar a pasta de distribuição.

4. Teste JavaScript

Importe a pasta WMK-JS-Demo, escolhendo o arquivo project.godot. Abra a cena principal e pressione F5.

Resultado esperado no console:
[JS] WMK_JS_OK

O marcador acima demonstra que uma cena Godot executou código JavaScript. Sem ele, não assuma que JS está habilitado.

Alterar o script e testar de novo

Abra welcome.js, acrescente outra chamada console.log("Meu teste WMK");, salve e execute novamente. Alterações apenas no script não exigem recompilação do editor.

5. Teste Lua 5.4

Importe WMK-Lua-Demo/project.godot e pressione F5.

Resultado esperado:
WMK_LUA_54_OK

A extensão Lua é instalada por projeto usando GDExtension; isso não significa que o Lua esteja embutido no núcleo do Godot.

6. Teste de movimentação 2D e 3D

Na branch wmk-js-ts-integration estão as pastas wmk-js/playground/2d e wmk-js/playground/3d. Abra cada project.godot e use as teclas W, A, S, D. Verifique se o personagem se move, se o chão existe e se o console mostra WMK_PLAYGROUND_2D_OK ou WMK_PLAYGROUND_3D_OK.

O Playground pertence a uma compilação mais recente, por isso não está garantido que venha no ZIP da execução 43905108907. As cenas 2D/3D precisam de validação independente.

7. Testar o WMK CodeVerse Studio (aplicativo web separado)

Este site não é o editor Godot. Ele serve para organizar códigos, templates e conversar com assistentes IA.

cd D:\Ferramentas\WMK-CodeVerse\wmk-studio
Copy-Item .env.example .env
node server.mjs

Abra http://127.0.0.1:4178. Exige Node.js 20+; configure chaves somente no arquivo .env, nunca na interface ou no GitHub. O Monaco é carregado de CDN e requer Internet; existe editor alternativo.

8. Erros comuns

O Windows bloqueia o executável

Baixe somente do repositório controlado por você. Verifique a origem e o hash SHA256 divulgado na execução; não desative antivírus nem recursos de segurança para forçar a execução.

O script JS não abre

Confirme que usou o editor especial com GodotJS e não a versão oficial padrão do Godot.

GodotSharp não encontrado

Extraia o ZIP novamente mantendo toda a estrutura de diretórios.

Lua não executa

Abra o projeto com a extensão correspondente e consulte a aba de erros. A DLL Lua precisa ser compatível com Windows x64.

Monaco não carrega no Studio

Verifique conexão com Internet; o editor de texto alternativo deve aparecer automaticamente.
